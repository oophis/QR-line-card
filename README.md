# QR-line-card

การ์ดดิจิทัลที่เปิดด้วยการสแกน QR — **หน้า 1 และ 2 ดูได้ตลอด ส่วนหน้า 3 เลือกได้ครั้งเดียว และดูได้ครั้งเดียว**

สแกนใหม่หรือเปิดใหม่ จะเห็นแค่หน้า 1 กับ 2 ส่วนหน้า 3 จะถูกปิดผนึกถาวร เลือกใหม่ไม่ได้

static site ล้วน — ไม่มี backend ไม่มี build step ไม่มี dependency ที่ต้องติดตั้ง

---

## หน้าตาการทำงาน

| หน้า | พฤติกรรม |
|---|---|
| หน้า 1 | เปิดดูได้ไม่จำกัด |
| หน้า 2 | เปิดดูได้ไม่จำกัด |
| หน้า 3 | เลือก **ซ้าย** หรือ **ขวา** ได้ครั้งเดียว → เห็นเนื้อหาฝั่งที่เลือกครั้งเดียว → ปิดผนึก 🔒 |

สถานะของหน้า 3 มี 3 แบบ

| สถานะ | เมื่อไหร่ | ผู้ใช้เห็นอะไร |
|---|---|---|
| `choose` | ยังไม่เคยเลือก | ปุ่มเลือก ซ้าย / ขวา |
| `reveal` | เพิ่งกดยืนยันใน session นี้ | เนื้อหาฝั่งที่เลือก + ปุ่มปิดผนึก |
| `sealed` | เคยเลือกไปแล้ว | 🔒 บอกแค่ว่าเลือกฝั่งไหน เมื่อไร — ไม่แสดงเนื้อหา |

**จังหวะการปิดผนึกสำคัญมาก:** ระบบบันทึกทันทีที่กด "ยืนยัน" ไม่ใช่ตอนปิดหน้า
ถ้าผู้ใช้รีเฟรชหรือปิดเบราว์เซอร์ระหว่างอ่าน = ใช้สิทธิ์ไปแล้ว ตรงตามเงื่อนไข "ดูได้ครั้งเดียว"

## แก้เนื้อหาการ์ด

แก้ไฟล์เดียวคือ [`assets/card-data.js`](assets/card-data.js)

```js
window.CARD_DATA = {
  defaultCardId: 'demo',
  cards: {
    demo: {
      brand: 'LINE QR Card',
      pages: [
        { eyebrow: 'หน้า 1', title: '...', body: ['บรรทัดที่ 1', 'บรรทัดที่ 2'], note: '...' },
        { eyebrow: 'หน้า 2', title: '...', body: ['...'] },
      ],
      gate: {
        title: 'เลือกหนึ่งอย่าง',
        options: {
          left:  { label: 'ซ้าย', icon: '🎁', title: '...', body: ['...'], code: 'LEFT-2026' },
          right: { label: 'ขวา',  icon: '✨', title: '...', body: ['...'], code: 'RIGHT-2026' },
        },
      },
    },
  },
};
```

- `pages[]` จะมีกี่หน้าก็ได้ ไม่จำเป็นต้อง 2 — หน้าสุดท้ายจะเป็นหน้าเลือกเสมอ
- `code` เป็น optional ตัดออกได้ถ้าไม่ต้องการโชว์รหัส

### หลายการ์ดใน deployment เดียว

เพิ่ม key ใหม่ใน `cards` แล้วเข้าด้วย `?c=<id>`

```
https://<user>.github.io/qr-line-card/?c=birthday-2026
```

แต่ละ id เก็บสถานะ "เลือกแล้ว/ดูแล้ว" แยกกัน

## Deploy ฟรีด้วย GitHub Pages

1. push ขึ้น branch `main`
2. ไปที่ **Settings → Pages → Source** เลือก **GitHub Actions**
3. workflow ที่ [`.github/workflows/pages.yml`](.github/workflows/pages.yml) จะ deploy ให้อัตโนมัติทุกครั้งที่ push

จะใช้ Cloudflare Pages หรือ Netlify ก็ได้เหมือนกัน — ชี้ไปที่ root ของ repo ไม่ต้องตั้ง build command

## ⚠️ ข้อจำกัดที่ควรรู้

สถานะเก็บฝั่ง client (`localStorage` → cookie → memory ตามลำดับที่ใช้ได้)
ซึ่งผูกกับ **เบราว์เซอร์ + เครื่อง** ไม่ใช่ตัวบุคคล ดังนั้น:

- เปลี่ยนเครื่อง เปลี่ยนเบราว์เซอร์ เปิดโหมดไม่ระบุตัวตน หรือล้างข้อมูลเบราว์เซอร์ → เลือกได้ใหม่
- คนที่เปิด devtools เป็น ลบ key ทิ้งได้

เหมาะกับการ์ดของขวัญ เซอร์ไพรส์ หรือกิจกรรมสนุก ๆ ที่กันคนทั่วไปพอ
**ถ้าต้องกันจริงจัง** (เช่น คูปองที่มีมูลค่า) ต้องมี backend ออก token ต่อ 1 QR แล้วเช็คฝั่ง server ซึ่งไม่ฟรีเสมอไป

มี fallback เป็น cookie ไว้แล้ว เพราะ in-app browser ของ LINE บางเวอร์ชันปิด `localStorage`
